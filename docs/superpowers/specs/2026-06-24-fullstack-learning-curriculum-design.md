# 16 周前端转全栈课程设计

## 1. 学习者现状

- 当前角色：React 前端开发者
- 前端方向：Next.js
- 后端基础：接触过 Node.js
- 薄弱项：SQL、PostgreSQL、Docker
- 可投入时间：每天稳定 3–4 小时，工作日与周末一致
- 主线项目：多人协作任务管理系统

## 2. 课程目标

16 周结束时，学习者应能独立完成以下工作：

1. 使用 TypeScript、Next.js 和 NestJS开发前后端分离应用。
2. 使用 PostgreSQL 设计关系模型、编写 SQL、创建索引并处理事务。
3. 使用 Prisma 管理 Schema、Migration 和常用数据访问。
4. 实现基于 Session 和 HttpOnly Cookie 的认证系统。
5. 实现团队、项目、成员和任务的 RBAC 权限控制。
6. 编写单元测试、API 集成测试和浏览器端到端测试。
7. 使用 Docker Compose 运行 Web、API、PostgreSQL 和 Redis。
8. 配置 CI/CD、日志、错误监控，并将系统部署到可公开访问的环境。
9. 能解释一个请求从浏览器、网络、服务端到数据库并返回响应的完整过程。

## 3. 教学方式

采用项目驱动、螺旋式学习：

- 每周围绕一个项目里程碑学习必要知识。
- 先通过小型独立案例理解原理，再实现到主线项目。
- 每周必须产生可运行、可测试、可提交的成果。
- SQL 和 Docker 安排额外练习，不仅依赖 ORM 和复制配置。
- 控制技术范围，第一版不引入微服务、Kubernetes、Kafka、GraphQL 或复杂 DDD。

## 4. 每日时间结构

每天总投入 3–4 小时：

- 45–60 分钟：阅读原理、官方文档并记录关键概念。
- 45–60 分钟：完成独立代码案例。
- 90–120 分钟：实现主线项目。
- 15–30 分钟：运行测试、整理笔记并创建 Git 提交。

每周安排：

- 第 1–6 天：学习和开发。
- 第 7 天：复盘、补缺、重构、验收和周总结。

## 5. 技术栈

- 语言：TypeScript
- 前端：React、Next.js App Router
- 后端：Node.js、NestJS
- 数据库：PostgreSQL
- ORM：Prisma
- 缓存与基础设施：Redis
- API：REST、OpenAPI
- 认证：Session、HttpOnly Cookie
- 测试：Vitest 或 Jest、Supertest、Playwright
- 工程：pnpm Workspace、ESLint、Prettier、Git
- 部署：Docker、Docker Compose、反向代理、HTTPS
- CI/CD：GitHub Actions
- 可观测性：结构化日志、Sentry 或同类错误监控

## 6. 主线项目范围

### 第一阶段功能

- 健康检查接口
- 用户注册、登录、退出和当前用户查询
- 团队创建和团队成员管理
- 项目创建和项目成员管理
- 任务创建、查看、修改和删除
- 任务负责人、优先级、状态和截止日期
- 搜索、筛选、排序和分页
- 任务评论
- 管理员、成员、访客三级权限

### 第二阶段功能

- 操作审计日志
- 站内通知
- Redis 缓存和接口限流
- 文件上传
- 关键业务测试
- Docker 化和 CI/CD
- 生产环境部署、日志和错误监控

## 7. 课程阶段

### 第 1–2 周：Node.js、TypeScript 与 HTTP

完成原生 HTTP 服务和 NestJS 基础骨架，理解请求、响应、异步流程和异常处理。

### 第 3–4 周：PostgreSQL 与数据建模

先使用 SQL 手工建表和查询，再接入 Prisma；完成用户、团队、项目、成员和任务模型。

### 第 5–7 周：后端业务

实现分层、参数验证、统一错误、CRUD、分页、筛选和 OpenAPI 文档。

### 第 8 周：认证与安全

完成密码哈希、Session、Cookie、RBAC、CORS、CSRF 和限流基础。

### 第 9–10 周：Next.js 与前后端联调

完成登录、项目列表、任务看板、表单、请求状态和权限页面。

### 第 11–12 周：测试

完成 Service 单元测试、PostgreSQL 集成测试、认证权限测试和 Playwright 核心流程。

### 第 13–14 周：Docker 与部署

完成多阶段镜像、Docker Compose、数据持久化、反向代理、HTTPS、备份和恢复。

### 第 15–16 周：CI/CD 与工程收尾

完成自动检查、构建、部署、日志、监控、性能优化和项目文档。

## 8. 每周验收规则

每周至少满足：

1. 一个可运行的功能或基础设施成果。
2. 一个脱离主项目的知识案例。
3. 一组可重复执行的验证命令。
4. 一份周总结，包含掌握内容、错误记录和下周风险。
5. 代码进入版本控制，提交信息能够说明本次变化。

每个功能的完成定义：

- 正常流程可运行。
- 输入错误有明确响应。
- 权限边界已验证。
- 至少覆盖关键测试。
- README 或接口文档已同步。

## 9. 最终验收

学习者需要独立完成一次演示：

1. 从空数据库执行 Migration 和种子数据。
2. 启动完整本地环境。
3. 注册用户并创建团队、项目和任务。
4. 演示不同角色的权限边界。
5. 演示搜索、分页、评论和通知。
6. 运行全部自动化测试。
7. 通过 Docker Compose 启动系统。
8. 展示 CI/CD 结果和线上环境。
9. 完成一次数据库备份和恢复。
10. 解释系统架构、安全措施、索引选择和主要技术权衡。

## 10. 明确不包含的内容

第一轮 16 周不包含：

- 微服务拆分
- Kubernetes
- Kafka
- 分布式事务
- Event Sourcing
- 复杂领域驱动设计
- 多云和高可用集群

这些内容只有在单体应用的数据库、测试、部署和故障定位能力达到最终验收标准后再学习。
